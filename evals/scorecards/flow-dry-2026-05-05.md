## Score Guide

- `0`: wrong flow, unsafe behavior, or misleading guidance.
- `1`: partially useful but needs human rescue.
- `2`: mostly correct with minor friction or missing context.
- `3`: correct flow, clear gates, useful next step, and good user-facing report.

## Checks

- Router check: Pass. `SKILL.md` routes check-in, upload, upgrade, account connection, and comment/reply prompts to guided flows.
- Boundary check: Pass. Installable skill files do not reference `evals/`, scorecards, live evals, `repo-workflows/`, `research/`, backend inventories, or `mvp-scope`.
- REST-only check: Pass. GraphQL appears only as REST-only prohibition language.
- Approval gate check: Pass. Upload, upgrade/cancel, account connection, password setup, and public comments all require explicit approval or user action.
- UX check: Pass with gaps. Current flows give useful next steps; more flows are still needed for discovery, folders, onboarding, and error recovery.
- Endpoint reference check: Pass. Flow files route endpoint detail to `skills/auth.md`, `skills/account.md`, `skills/social.md`, and `skills/items.md`.
- Secret check: Pass. No real-looking Wondermint secrets were introduced.

## What Worked

- Flow files are user-facing and do not include repo-development procedure.
- `SKILL.md` is becoming a clearer router without growing much.
- Public or billing actions have approval gates before side effects.
- Check-in now routes naturally into comment/reply, upload, discovery, or account docs.

## What Confused The Agent

- `connect-account.md` handles both account-connection directions in one file. That is efficient, but future scenario testing should confirm agents choose the right branch reliably.
- `SKILL.md` still has direct links to detailed domain docs for some tasks while newer flows exist for others; this is acceptable during the transition but should be cleaned up as more flows are added.

## Missing Context

- No independent fresh-agent dry run has tested whether another agent follows these flows from realistic prompts.
- No live behavior was tested.
- There are no guided flows yet for discovery, folder organization, onboarding, or error recovery.

## Recommended Changes

- Add a fresh-agent dry eval before tagging a release.
- Add guided discovery and error-recovery flows next.
- Consider splitting account connection into two files only if dry evals show branch confusion.
